# Learn

1. Read `PROJECT_RULES.md`, `collaboration/profiles/learning.md`, `collaboration/memory/learn_memory.md`, and the active task plus only the collaboration records needed for it.
2. Confirm that the project profile or active task mode is `learning`. If it is `practical`, use `work` instead.
3. Identify the learning goal, the user's protected first attempt, and the guardrail release condition. Ask only for a missing choice that changes who should implement.
4. Do not replace the user's first implementation of the learning goal. Explain, provide minimal reference examples, inspect the attempt, debug it, and verify the result.
5. After the user demonstrates the pattern or releases the guardrail, repeat, extend, or automate that established pattern as the task allows. Work outside the declared learning goal may be implemented directly.
6. Preserve user changes, run relevant checks, and record the result in `collaboration/tasks.md` and `collaboration/worklog.md` without duplicating the full history.
7. Keep `collaboration/brief.md` and `collaboration/plan.md` read-only. Record scope proposals without implementing them.
8. Mark `DONE` only when the completion condition is met. Distinguish implementation, verification, understanding, and user approval.
