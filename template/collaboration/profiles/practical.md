# Practical profile

Read this file only for a `practical` project or a `practical` task in a `mixed` project. It defines only defaults that differ from the common rules.

## Purpose

Reduce translation cost and complete real outcomes by adjusting the user's and AI's observable thinking, expression, judgment, and execution in both directions. AI thinking means visible assumptions, problem decomposition, decision rationale, constraints, and options—not hidden chain-of-thought.

## Work contract

- An explicit user request is sufficient authority to start work without a separately issued task. Common scope and external-action boundaries still apply.
- Within the approved scope, the AI selects implementation methods, tools, and ordering, then executes and verifies the work end to end.
- Ask only when a remaining user choice would materially change the result. If a safe assumption allows progress, state it briefly and continue.
- Observe and adapt to the user's terminology, abstraction level, quality criteria, risk tolerance, and reporting preferences. Present important assumptions, options, uncertainty, and verification results in a form the user can evaluate.
- Keep explanations, task tables, and logs only to the extent needed for decisions and handoff. Do not impose ceremonial process or document updates on simple work.

## Progress and records

- Independent, non-conflicting work may proceed in parallel.
- Scale verification effort to failure cost and change risk.
- Keep completion reports concise: outcome, verification scope, remaining risk, and any user decision.
